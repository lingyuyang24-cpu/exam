# 可复现演示提示词

所有输入均为虚构演示数据。真实运行记录位于 evidence；以下仅为输入。

## 会话 A · 代码开发

第一轮：请在 project 目录开发一个 Python CSV 数据质量检查工具。支持输入 CSV 路径，检查每列缺失值和完整重复行（除首次出现外的重复行数），输出 JSON 报告。提供 README 和至少 4 个 unittest 测试，实际运行测试。只使用 Python 标准库，不安装依赖。

第二轮：在刚才的工具基础上增加 --dedupe-output 参数，把去重结果写入指定新文件，保留首个出现的完整行，保持原始输入不变。完整重复行按 CSV 解析后的原始字段逐一比较，空白字符不同不算重复；缺失值判断仍可去除首尾空白。报告的重复行数与去重输出必须一致。拒绝将去重结果写回输入文件。只做必要的局部修改，补充边界测试并运行全部测试，在回复中说明实际结果。

## 会话 B · 工作材料

先上传 inputs/sales.csv 和 inputs/meeting_notes.md。

第一轮：请分析 uploads 中的销售数据和会议记录。第一版按全部订单统计，以数量乘单价为订单金额。在 outputs 生成 report.md 和 summary.csv。CSV 列固定为 region,total_sales，按区域汇总金额。报告包含区域销售额、产品排名、各订单状态金额、会议待办及待确认问题，注明材料来源与统计口径。使用 Python 计算并保留分析脚本，不要编造利润或取消原因。

第二轮：将报告和 summary.csv 改为只统计已完成订单，CSV 仍为 region,total_sales 两列。报告压缩为一页管理层摘要，保留总金额、区域金额、重要结论、负责人和期限。实际重新运行分析脚本并验证关键数字。

## 展示顺序

1. 开始会话 A 的第一轮任务，展开真实命令记录。
2. 创建会话 B、上传材料并开始分析，切换回会话 A。
3. 刷新页面，检查会话、任务状态及事件仍存在。
4. 两个会话分别追加第二轮要求，预览文件并下载成果包。
5. 展示代码测试结果与销售金额的独立验证结果。
6. 重启容器，确认历史与文件仍可访问；执行中的任务应标记中断。
